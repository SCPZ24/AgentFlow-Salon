# A02 · Pi 上下文装配｜讲者备注

主线约 5 分钟，另留 1 分钟提问。8 个阶段、17 个可暂停动作；每幕只指向一个来源和一个去向。

## 演示操作

加载后暂停。`→` / `Space` 前进，`←` 后退，`P` 重播本步，`R` 重置，`C` 打开或收起控制层，`Esc` 关闭控制层。阶段名称可以直接点击。

每步先定位 300ms，再移动 1000ms，落位呈现结果 500ms，随后停住。动画中再按前进，只完成本步。回退、跳阶段和重置直接显示完整状态；减少动效保留路径与结果。

控制层提供全屏与减少动效。默认遵循系统的减少动态效果设置；URL 中已有 `motion` 参数时优先使用 URL。刷新恢复 hash 状态。投影前在现场后排检查关键文字；本地静态帧不能证明真实投影效果。

静态备份由网页使用的同一份 SVG 场景直接导出，不是浏览器截图。页面本身无远程资源、后端和构建依赖。导出 PNG 的维护脚本需要开发环境中已有的 `sharp`，不影响 HTML 离线运行。

## 关键区别

- `system_prompt` / `tools` / `messages` 是本场的逻辑分组，不声称是某个 provider 的原始请求结构。
- 默认基础提示词中的工具介绍是文字；`tools` 中的是可调用定义。
- `SYSTEM.md` 只替换基础块；后续追加的补充、项目规范、技能目录和 cwd 保留。当前构建行为以原制作脚本的核验为依据，不扩展成所有版本永久不变的协议。
- Skills 的名称/描述先被发现，正文在读取完成后进入工具结果路径。步骤 12 只有读取请求，步骤 13 才有正文。
- 图中的 `AGENTS` 概括全局与当前项目两个示例，不展开所有祖先目录规则。规则是模型指令，不是权限沙箱。
- Prompt 模板展开为用户请求；会话历史不会因此自动获得 system 级别。
- 整理旧历史用摘要替换较早消息，近期用户请求和工具结果保留；不改变模型权重。

## 可选对照操作

按 C 呼出控制层：

1. **自定义基础**：切换默认规则与 SYSTEM.md。若当前已在后面的步骤，保留当前消息历史，只演示基础替换；若仍在准备阶段，则进入步骤 7。
2. **冗长 / 冲突样本**：显示过期命令、旧框架、无关日志，并标出 AGENTS 补充的冲突来源。长度条只表示教学构造的相对长度，不是 token 计数或性能测量。
3. **本地深色主题**：只改变左下角本地预览，不改变三个请求区域。扩展既可能改输入，也可能只影响 UI，不能把二者一概而论。
