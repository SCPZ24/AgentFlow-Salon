# A01 · ReAct 与上下文增长｜讲者备注

主线约 3 分钟，测试失败分支约 30 秒。屏幕上的 Call 只统计模型调用，不统计工具执行。

## 演示操作

加载后暂停。`→` / `Space` 前进，`←` 后退，`P` 重播本步，`R` 重置，`C` 打开或收起控制层，`Esc` 关闭控制层。阶段名称可以直接点击。

每步先定位 300ms，再移动 1000ms，落位呈现结果 500ms，随后停住。动画中再按前进，只完成本步。回退、跳阶段和重置直接显示完整状态；减少动效保留路径与结果。

控制层提供全屏与减少动效。默认遵循系统的减少动态效果设置；URL 中已有 `motion` 参数时优先使用 URL。刷新恢复 hash 状态。投影前在现场后排检查关键文字；本地静态帧不能证明真实投影效果。

静态备份由网页使用的同一份 SVG 场景直接导出，不是浏览器截图。页面本身无远程资源、后端和构建依赖。导出 PNG 的维护脚本需要开发环境中已有的 `sharp`，不影响 HTML 离线运行。

## 必须停住的地方

- `#step=1`：输入在请求开始时冻结，文件正文还没有读到。
- `#step=6`：读取结果出现在“下轮新增”；本轮快照未改变。
- `#step=7`：新一轮的 messages 增加 `read → 源码`。可问观众“比上一轮多看到了什么？”
- `#step=10`：文件显示 diff，测试明确标为未运行。
- `#step=16`：测试输出进入下轮区域，还没有第 4 次模型调用。
- `#step=19`：四次调用结束，候选交付仍然等待人类验收。

历史条目的显示是摘要式排版，不代表系统已经执行了上下文压缩。每个条目都保留对应工具名称和结果。示意中的“决策中”不是真实隐藏推理记录。

## 失败分支

在步骤 14–16 点击“演示测试失败”，或使用 `#branch=fail&step=0`。分支不伪造修复成功。

1. `#branch=fail&step=0`：测试失败；结果仍然是一条有效反馈。
2. `#branch=fail&step=1`：失败结果进入历史，不能跳过。
3. `#branch=fail&step=2`：Call 4：带着失败证据，再做决策。
4. `#branch=fail&step=3`：重新定位与修复，不自动宣告成功。

“返回测试主线”回到步骤 14，即运行测试的位置。
