HTML-PPT

转到核心工具：如果 AI 做传统 PPT 经常失控，那就把 PPT 变成 AI 更擅长的 HTML。

既然 AI 做不明白 PPT...

改用 HTML

github.com/lewislulu/html-ppt-skill
AI 原生
化静为动
重点解释两点：HTML 是文本结构，AI 更容易稳定生成；同时浏览器天然支持动画、交互、响应式和导出。
这里直接让动图说话。可以补一句：我们要的不是“像 PPT 的网页”，而是能演示、能交互、能导出的网页化幻灯片。

SKILL 安装

先得有 nodeJS 环境

npm install openskills
cd path/to/working/directory

openskills install https://github.com/lewislulu/html-ppt-skill

openskills sync
按三步讲即可：Node 环境、全局 openskills、在工作目录安装并同步 skill。

Comparison

DeerFlow 与其他 Agent

Agent名称
与 DeerFlow 的核心对比
DeerFlow
开源多智能体 SuperAgent 框架，面向研究 + 作品产出；代码能力稍弱
LobeHub
体验优先的多模型统一平台，交互极佳、部署极简单；执行能力弱，多智能体协作浅
Hermes
极简单智能体执行引擎，无框架依赖、代码透明、部署成本极低；无并行、记忆弱、安全性差
Claude Code
专业编程助手，编码能力 SOTA，IDE / CLI 深度集成；仅支持 Claude 模型，研究能力几乎为零
表格页要快讲，强调 DeerFlow 的定位：更像研究和作品产出的端到端 SuperAgent，而不是单纯聊天或编码助手。

Setup

配置

git clone https://github.com/bytedance/deer-flow

cd deer-flow

cp config.example.yaml config.yaml
cp .env.example .env
配置好模型和 API KEY。
直接用 make 来启动。
遇到棘手的情况都直接问Cursor
这页可以结合实际经验讲：配置不复杂，但不同环境启动时容易碰到依赖和端口问题，直接让 Cursor 边报错边修。

Frontend Workflow

AI前端技巧

进入最后一段：AI 前端不是只靠模型能力，更要靠组件、动效库、开发服务器和人工微调链路。

huashu-design

让 AI 的前端不像 AI 做的

这里突出 huashu-design 的作用：不是替 AI 写更多代码，而是给它审美约束、组件意识和更像设计师的判断。

GSAP

一个开源的动画库，可以用简单的 API 在网页上做动画

from to

GSAP-skills：让 AI 更精准地控制 GSAP。

解释 GSAP 的好处：它把复杂动画压成 from/to/timeline 这种 API，AI 更容易稳定调用，也更方便你微调节奏。

其他前端技术栈

three.js
vue / react
这里可以轻轻带过：three.js 适合 3D 和沉浸式场景，Vue/React 适合工程化和组件复用。

在开始做前端之前

npm run dev

默认在 localhost:5173

这里强调一点：前端工作一定要跑起来看。只看代码不看浏览器，很容易生成看似对、实际崩的界面。
